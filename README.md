# Insurance Underwriting Evaluation System

A beginner-friendly synthetic-data project that demonstrates insurance quote eligibility, transparent premium calculation, underwriting referrals, policy lifecycle records, renewals, endorsements, and anomaly validation.

> **Important:** This is an educational demonstration using synthetic data. It is not intended to make real insurance, legal, financial, or regulatory decisions.

## Features
- 3,000 synthetic applicants and assets
- 4,000 quote submissions
- Product, coverage and risk-factor master data
- Deterministic premium formula and rule-based decisions
- Policy, endorsement, renewal and underwriting-decision records
- Separate `ground_truth.csv` labels for known test anomalies
- Validation summary and detected issue report
- Streamlit dashboard
- SQLite schema and automated unit tests

## Setup (Windows)
1. Install Python 3.10 or newer.
2. Open this folder in VS Code.
3. Open Terminal > New Terminal.
4. Create and activate an environment:

```powershell
python -m venv .venv
.venv\Scripts\activate
```

5. Install dependencies:

```powershell
pip install -r requirements.txt
```

6. Generate data:

```powershell
python generate_data.py
```

7. Run validation:

```powershell
python validate_data.py
```

8. Run unit tests:

```powershell
python -m unittest discover -s tests -v
```

9. Start the dashboard:

```powershell
streamlit run app.py
```

## Rules
Premium formula:

`premium = requested_coverage * product_base_rate * risk_multiplier`

Risk multipliers are Low = 1.0, Medium = 1.5, High = 2.5. The example product rates and limits are synthetic and configurable in `underwriting.py`.

A policy must not be issued unless the quote is approved, the customer has accepted, payment is confirmed, and required approval authority is satisfied.

## Data outputs
The `data/` folder is generated by the script and contains CSV tables, `source_manifest.json`, `validation_summary.json`, and `detected_issues.csv`. `ground_truth.csv` is kept separate from the quote decision inputs.

## Reproducibility
The generator uses fixed seed `20261022`. Run it twice and compare the generated CSV checksums to verify reproducibility. Generated timestamps and values are synthetic.

## Limitations
This is a starter implementation. It demonstrates the required workflow but should be extended before claiming production readiness. In particular, implement stronger lifecycle transition checks, comprehensive overlap detection, database persistence, actor authentication, and a full ground-truth-to-detection scorecard.
